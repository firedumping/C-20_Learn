# 第 14 章：模块与协程：原理、现状与选型

## 学习目标

- 理解模块与传统头文件+翻译单元的区别。
- 知道导出、导入、模块接口单元和实现单元的基本结构。
- 理解协程挂起与恢复的机制，以及协程不是线程。
- 认识协程所需的 promise、awaiter 和调度器责任。
- 能在工具链支持有限时选择成熟的替代方案。

## 1. 为什么有模块

传统 `#include` 是预处理文本复制。大型项目中它带来：

- 重复解析头文件。
- 宏泄漏。
- ODR 和包含顺序问题。
- 头文件依赖导致的编译缓慢。

模块把接口编译为可导入单元：

```cpp
// math.cppm
export module math;

export int add(int a, int b) {
    return a + b;
}

export namespace math {
int square(int value);
}
```

消费：

```cpp
import math;

int main() {
    return math::square(add(2, 3)) == 25 ? 0 : 1;
}
```

`export` 决定哪些声明对导入者可见。未导出的内容不会通过文本包含泄漏到使用者。

## 2. 模块单元

常见结构：

```cpp
// math.cppm
export module math;

export int add(int, int);

// math_impl.cpp
module math;

int add(int a, int b) {
    return a + b;
}
```

这里第一个文件是接口单元，第二个是实现单元。编译器支持程度、文件扩展名和构建系统命令各不相同。不要假设所有工具链能用同一套源文件扩展和命令。

模块还可以使用模块分区，但那是大型项目的维护话题。初学阶段先用：

- 稳定接口模块。
- 少量实现模块。
- 明确约定模块名和文件对应关系。

## 3. 模块不是万能封装

仍然需要设计良好的公共 API：

- 导出过多类型会让 ABI 和依赖难以控制。
- 模块不保证线程安全。
- 模块不会自动解决循环依赖；只是给依赖建模提供另一种手段。
- 与第三方头文件的组合需要工具链支持 `import std` 或 `import header_unit` 等能力，生态仍不统一。

如果编译器/CMake/IDE 对模块支持不稳定，可以先用传统头文件完成业务学习，不要把“成功配置模块”误当成本课程的核心目标。

## 4. 协程是什么

普通函数调用时，控制从调用者进入函数，函数返回后恢复调用者。协程允许函数：

- 返回值、
- 挂起当前执行点、
- 把控制交还给调用者、
- 之后从挂起点恢复。

协程仍是单线程执行流。它不会自动创建线程，也不会自动并行。

语言提供三个关键字：

```cpp
co_await
co_yield
co_return
```

一个函数只要在函数体中直接出现其中之一，就是协程。

## 5. 最简单的生成器直觉

协程适合表达“按需产生值”的序列：

```cpp
Generator<int> numbers() {
    for (int i = 0; i < 3; ++i) {
        co_yield i;
    }
}
```

调用者每次请求下一个值时，协程从上次 `co_yield` 后继续，而不是从头执行。

但是 C++20 没有标准 `Generator<T>`。需要自己实现协程返回类型，或使用库（如 C++23 的 `std::generator` 或第三方库）。这意味着协程的“语法”是标准的，但完整运行框架不一定标准现成。

## 6. promise、awaiter 和状态机

编译器会把协程函数改写为状态机。返回类型通常包含 `promise_type`：

```cpp
struct promise_type {
    MyCoroutine get_return_object();
    std::suspend_never initial_suspend();
    std::suspend_always final_suspend() noexcept;
    void return_void();
    void unhandled_exception();
};
```

调用者与协程之间通过 promise 和 awaiter 协议交互。要实现一个安全生成器，至少要处理：

- 协程状态分配和释放。
- 初始挂起与最终挂起。
- 当前值存取。
- 恢复与完成检测。
- 异常传播。
- 迭代器生命周期和禁止复制。

这不是“写起来短的异步代码”就能概括的。错误的协程框架通常留下泄漏、悬空引用或永久挂起。

## 7. `co_await` 的心智模型

简化流程：

1. 求值 `co_await` 的等待对象。
2. 调用 awaiter 的 `await_ready()`，若已就绪则直接继续。
3. 否则调用 `await_suspend(handle)`。
4. 挂起后，某个调度者稍后调用 `handle.resume()`。
5. 恢复后调用 `await_resume()` 得到结果。

真实的挂起、恢复和调度由你的 awaiter 和运行时库定义。标准库只规定协议，不提供成熟的通用异步运行环境。

## 8. 协程与线程、任务的区别

| 概念 | 是否自动并发 | 典型用途 |
|---|---:|---|
| 普通函数 | 否 | 同步计算 |
| 协程 | 否 | 可挂起状态机、生成器、异步 I/O |
| `std::thread` | 是（操作系统线程） | CPU/阻塞任务 |
| 线程池任务 | 取决于运行库 | 有界并发执行 |

I/O 异步场景下，协程可以把回调链写成顺序代码，但需要一个调度器和真实 I/O 后端。单纯使用协程不会让磁盘或网络变快。

## 9. 学习模块与协程的正确顺序

先掌握：

- RAII、移动语义和异常安全。
- 模板与类型擦除。
- 并发同步和生命周期。
- 构建系统的 target 和依赖管理。

然后再实现协程。否则最容易出错的不是语法，而是协程帧里保存了已经失效的引用，或调度器销毁后仍有恢复任务。
