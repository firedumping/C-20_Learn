# C++ 系统方向求职冲刺包

> 生成日期：2026-10-27  
> 目标：复习 C++ 与系统基础，并完成一个可用于求职展示的端侧设备控制项目

## 1. 为什么单独建立这个冲刺包

WSL2 中已有的 `/home/ring/C-20_Learn` 已经包含一套较完整的 C++20 课程，不需要重新从语法开始学习。本冲刺包只补充从“会 C++”到“能应聘端侧系统软件岗位”之间的内容。

已有内容与本冲刺包的关系：

| 已有内容 | 已覆盖的能力 | 本冲刺包如何处理 |

### 检索后确认的主要缺口

现有课程没有完整覆盖以下内容：

1. 事件循环的线程归属、调度顺序、定时器、停止和重入语义。
2. 有界优先级队列在队列满、急停和关闭时的具体策略。
3. Linux 进程、文件描述符、非阻塞 IO、IPC、`epoll`、`strace`、`/proc` 等系统调试。
4. 串口或 CAN 场景下的粘包、半包、校验失败、重同步和超时。
5. 设备断线、服务重启、看门狗和故障注入。
6. 从独立模块到完整端侧项目的集成、观测和演示方法。

## 2. 学习目标

完成后应能够证明以下能力：

- 能解释对象的类型、所有权、生命周期和异常路径。
- 能编写安全的单线程事件循环，并说明它和线程池的适用边界。
- 能设计有界优先级队列，并解释队列满、任务饥饿和关闭时的行为。
- 能使用 GDB、sanitizer、日志、`strace`、`perf` 和 `/proc` 定位问题。
- 能实现增量二进制协议解析，并处理半包、粘包、校验失败和异常长度。
- 能处理设备断线、重连、超时和应用关闭，不只验证“正常路径”。
- 能把项目写成架构说明、性能数据和面试故事。

## 3. 六周路线

建议每周投入 15～20 小时的深度学习和编码时间。求职准备可以并行进行，不需要六周后再投简历。

| 周次 | 学习重点 | 必须完成的产出 |
|---|---|---|
| 第 1 周 | 生命周期、RAII、移动、错误安全、并发复习 | 完成既有 Lab 04、05、09、10、12 中至少 3 个，并写出三个对象生命周期案例 |
| 第 2 周 | 事件循环、任务队列、优先级、定时器 | 完成 Lab 01～02，并能画出一轮事件循环的状态图 |
| 第 3 周 | Linux 进程/线程、FD、IPC、GDB、`strace`、`perf` | 写一份真实排查记录，包含现象、假设、证据和结论 |
| 第 4 周 | 二进制协议、校验、半包/粘包、重连 | 完成 Lab 03～04，项目支持虚拟设备通信 |
| 第 5 周 | 故障恢复、看门狗、指标、故障注入 | 完成 Lab 05～06，演示至少四种故障场景 |
| 第 6 周 | 项目集成、性能基线、README、面试表达 | 完成演示版本、架构图、简历条目和三个面试故事 |

### 每天建议节奏

有整块时间时：

1. 30 分钟复习已有 C++ 章节或做旧 Lab。
2. 2 小时实现当天项目任务。
3. 30 分钟写测试和观察结果。
4. 30 分钟记录“今天做了什么选择、遇到什么问题、明天验证什么”。

时间较少时，至少保留“编码 45 分钟 + 复盘 15 分钟”，不要只阅读不动手。

## 4. 推荐使用顺序

1. 阅读 [C++ 与系统基础复习](01_cpp_system_foundations.md)。
2. 在 WSL2 中完成 [新增练习](labs/README.md)。先运行测试观察失败，再实现。
3. 阅读 [EdgeBot 旗舰项目](02_edgebot_project.md)，选择 Linux 虚拟设备版本作为 MVP。
4. 第 4 周开始投递，根据面试反馈调整项目重点。
5. 使用 [掌握度、面试与简历验收](03_mastery_and_interview.md) 进行阶段检查和表达训练。

## 5. 学习规则

### 必须做到

- 每个练习先写测试输入和预期结果，再写实现。
- 所有代码至少用高警告级别编译一次。
- 内存和并发问题优先使用 ASan/UBSan/TSan，而不是反复加 `cout`。
- 性能结论来自同一环境下的基线对比。
- 每个失败场景都要说明状态是否恢复、资源是否释放、用户看到什么。
- 面试材料只写真实完成内容，不把课程学习写成生产成果。

### 不要做

- 不要重新从头刷完整个 C++ 语法课程。
- 不要为了使用 C++20 特性而使用 Ranges、协程或 Concepts。
- 不要用无限队列、无限重试或无限创建线程隐藏设计问题。
- 不要先接 OpenHarmony、ROS2 和真实硬件再加测试。
- 不要让项目同时承担视觉、SLAM、AI 推理和复杂 UI。

## 6. 完成标准

最低可投递版本：

- 两套新增 Lab 通过，且能解释关键失败路径。
- 一个 Linux 事件循环服务可运行。
- 虚拟设备能发送数据、断线和恢复。
- 项目至少有三个可重复演示的异常场景。
- 有一份架构图和一份包含真实观测数据的排查记录。
- 两版简历均完成了项目描述和原有经历重写。

达到最低版本就应开始投递。后续根据面试反馈补齐 OpenHarmony UI、真实硬件或 ROS2 桥接。
