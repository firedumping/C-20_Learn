# 第 16 章：掌握度验收与后续路线

## 1. “精通”不是知道所有语法

对 C++ 的掌握更可靠地体现在：

- 能说明代码中的对象在哪里、谁拥有、何时销毁。
- 能解释某个设计为何满足错误安全、并发安全和性能目标。
- 能识别工具链和标准实现差异。
- 能通过测试、调试器和 profiler 验证结论。
- 能删掉不必要的抽象，而不是持续叠加模式。

本章是一个验收协议。不要只打勾；对每个条目给出一个你亲手写过的例子。

## 2. 语言与对象模型

能独立解释并演示：

- 值、对象、名字、作用域、存储期、生命周期。
- 左值/将亡值/纯右值。
- 复制消除、移动构造、移动后的有效状态。
- 引用折叠、转发引用和 `std::forward`。
- 成员初始化顺序和虚析构。
- 对象切片、悬空引用、迭代器失效。
- `constexpr`、`consteval`、`constinit`。
- `<=>` 的比较语义。

自测题：

1. 为什么一个返回局部变量引用的函数可能编译通过却在运行时失败？
2. `std::move(x)` 是否改变了 `x` 的值？
3. 为什么移动构造标记 `noexcept` 会影响 `vector` 扩容策略？
4. 什么情况下基类析构必须为虚函数？

## 3. 标准库与泛型

能独立完成：

- 根据数据规模和访问模式选择容器。
- 用 Ranges/算法组合实现词频、过滤、排序和分组。
- 解释比较器必须满足的严格弱序。
- 用 `optional`/错误类型/异常分别建模不同失败。
- 用 Concepts 约束模板接口。
- 理解 `span`、`string_view` 和拥有型容器的边界。

自测题：

1. 为什么 `std::vector` 通常是默认序列容器？
2. `map::operator[]` 在查找时可能做什么？
3. 视图何时悬空？
4. Concept 能保证哪些性质，不能保证哪些性质？

## 4. 资源与错误安全

能证明：

- 正常返回时资源释放。
- 异常抛出时资源释放。
- 不变量在失败后仍成立。
- 不用 `shared_ptr` 掩盖所有权混乱。
- 析构不抛出。
- 复制/移动操作不会导致双重释放或泄漏。

用 ASan/UBSan 或其他工具跑过至少一个故意错误和一个修复版本。

## 5. 并发

能独立做出一个安全的生产者/消费者或并行聚合：

- 共享状态清楚。
- 锁的保护范围清楚。
- 条件变量有谓词。
- 线程有退出路径。
- `jthread`/停止令牌的行为明确。
- 知道何时用原子，何时用锁。

能解释为什么“代码在 8 核机器上跑过 100 次”不能证明没有数据竞争。

## 6. 工程实践

至少完成一次：

- 从空目录创建 CMake target。
- 建立 Debug/Release 构建。
- 用高警告级别构建并解释修复。
- 写出覆盖边界的自动测试。
- 用调试器检查调用栈。
- 用 profiler 或基准找出热点。
- 写 README，包含输入格式、构建、运行、错误码和设计取舍。

## 7. 综合项目验收

综合项目必须通过：

- 空输入。
- 无效输入。
- 非法参数。
- 文件不存在。
- 正常小样本。
- 大规模样本。
- 至少一次强制异常路径（如文件读取失败）。

代码审查问题：

1. `parse_line` 的输入生命周期是什么？
2. 聚合器是否需要保存所有记录？
3. 状态码和小时统计选择什么容器，复杂度如何？
4. 平均耗时的分母是什么？
5. 严格模式遇到无效行时输出和退出码是什么？
6. 哪个错误路径最容易被测试遗漏？
7. 是否有可以利用 Ranges 但实际更难读的地方？
8. 性能基线在什么硬件、编译器和输入规模下测得？

## 8. 进阶主题路线

完成本课程后可继续：

1. **性能与底层**：缓存、SIMD、分配器、`std::pmr`、内存模型。
2. **库设计**：ABI、符号可见性、`std::expected`、类型擦除、Python/C API。
3. **并发进阶**：线程池、无锁数据结构、任务取消、异步 I/O。
4. **系统编程**：文件系统、网络、序列化、操作系统接口。
5. **C++23/后续标准**：`std::print`、`std::expected`、`std::mdspan`、`std::generator` 等。
6. **大型工程**：模块化、包管理、CI 矩阵、覆盖率、模糊测试。

请按项目需求学习，而不是按特性清单收集语法。
